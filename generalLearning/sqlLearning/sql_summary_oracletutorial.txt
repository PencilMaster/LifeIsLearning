======================= [QUERY, ALIAS, SELECT, ORDER BY, SELECT DISTINCT] =======================

Query:          Operation that retrieves data from one or more tables or views.
                -> Top-level SELECT statement is called a Query.
                -> Query nested within another SQL statement is called a subsquery.

Column Alias:   Example:  SELECT <t.first_name> || ' ' || <t.last_name> AS "Full Name" FROM <table> t;
                          -> Outputs Column named "Full Name" with all first and last names concatenated.

                Example:  SELECT <product_name>, <list_price> - <standard_cost> AS gross_profit FROM products;
                          -> Outputs Column "PRODUCT_NAME" and "GROSS_PROFIT" which contains the difference (<lp> - <sc>).
                          -> Using ORDER BY "gross_profit" [DESC | ASC] is possible.

Table Alias:    Example:  SELECT <e.first_name> employee, <m.first_name> manager
                          FROM <employees> e INNER JOIN <employees> m ON <m.employee_id> = <e.manager_id>;
                          -> Possible since execution chain is FROM -> INNER JOIN -> ON -> SELECT
                          -> Column/Table aliases are temporary names during execution of a query.

Select:         Way too much information for now. Will write rest first and any distinct Information to Select will be updated here.
                For now, now that it is evaluated after FROM. Not immediately after, but because of this aliases in FROM can be used in SELECT.

Order By:       Syntax:   ORDER BY <column_1> [ASC | DESC] [NULLS FIRST | NULLS LAST] {, <column> [ASC | DESC] [NULLS FIRST | NULLS LAST]};
                          -> Default ordering is ascending.
                          -> Influenced through locale defined in LC_COLLATE category. This defines string-comparison (ASC, DESC).
                          -> Positions of columns in SELECT are valid to use as well: ORDER BY 2 ASC, 1;
                Sort by function: Apply string or math functions to a column, ex.:  ORDER BY UPPER(<first_name>), <first_name>;
                                  -> This will output all names alphabetically and upper case first letter before lower case first letter.
                Sort by date:     Just ORDER BY <date_column> [ASC | DESC];

Oracle Fetch:   Syntax:   [OFFSET offset ROWS] FETCH NEXT [row_count | percent PERCENT] ROWS [ONLY | WITH TIES];
                          -> General: It limits the number of rows returned by a query.
                          -> Best used after ORDER BY -> FETCH.
                          -> Default value of offset: a) When offset <= 0 -> set to 0. 
                                                      b) If it is NULL or greater than returned rows -> no rows get returned.
                                                      c) If it is a fraction, the fraciton gets truncated.
                          -> Can use ROW instead of ROWS and FIRST instead of NEXT.
                          -> ONLY returns exact number of rows or percentage rows. WITH TIES returns additional rows with same sort key as the last column fetched.

Select Distinct:          DISTINCT is SQL standard. Always use DISTINCT. UNIQUE does the same but is Oracle flair and not standard.
                          -> SELECT DISTINCT <column_name> {, <column_name>} outputs each unique combination of column values from column_list as a record.
                          -> When you want to remove distinct col_values without having the column in your SELECT, you can use GROUP BY, beware of Explain Plan!
                          -> DISTINCT treats NULLS as same value.

                          
======================================= [FILTERING ROWS] =======================================

Where:          General:  Used to filter results in SELECT, DELETE and UPDATE etc. statements.
                          -> Used with [condition | IS NOT NULL | IN | NOT IN | LIKE | [NOT] BETWEEN ... AND ...]. 
                                  -> Also, combine conditions with [AND | OR | NOT].
                          -> Written directly after FROM [JOIN ON] and before GROUP BY. Very different from HAVING!
                          -> Evaluation Sequence: FROM -> WHERE -> SELECT -> ORDER BY.
                          
And:            General:  [TRUE AND TRUE] = TRUE | [NULL AND X] = [X AND NULL] = NULL | Otherwise = FALSE.
                          -> AND takes presedence. Without parantheses, AND is always evaluated first. For ex. in (... OR ... AND ...).
                          

Or:             General:  [TRUE OR X] = [X OR TRUE] = TRUE | [FALSE OR FALSE] = FALSE | Otherwise = NULL.
                          -> Without parantheses, OR is always evaluated after NOT and AND.
                          
In:             Syntax:   expression IN (<column_name>{, <column_name>}) OR expression_2 IN (...).
                          -> True if expression matches any values ina list or subquery inside (...).
                          -> Mostly used in WHERE clauses and result can be negated by using NOT IN operator.

Between:        Syntax:   expression BETWEEN low AND high.
                          -> Mostly used in WHERE clause        
                          -> Low and high can be literals or expressions
                          -> Negation is NOT BETWEEN, [exp < low or exp > high]
                          -> When using BETWEEN DATE x AND DATE y -- If date column has a time component, then it uses midnight per default.
                             In that case, better use <date_column> >= DATE '' AND <date_column> < DATE 'first day of next month'.

Like:           Syntax:   expression LIKE 'pattern'.
                          -> Wildcard characters: '%' matches zero or more characters, '_' matches a single character.
                          -> expression is <column_name> or subquery -> Subquery needs to return a single value (+ bad performance)
                          -> ESCAPE character '!' treats any wildcard immediately after ! as a regular character.
                          -> Negation is NOT LIKE

Is Null:        Syntax:   value IS [NOT] NULL
                          -> NULL is a marker that indicates, that data is missing, not applicable or unknown.
                          -> NULL cannot be compared using comparison operators. It is also not 0 or an empty string.


======================================== [MERGING ROWS] ========================================

General Joins:            1. You can use [AND] and [OR] in join_condition.
                          2. Watch out, there is a big difference between putting condition in JOIN ON () or in WHERE ().
                          3. If no join type is specified, then default is LEFT JOIN.
                          4. Empty column values will be filled with NULL.

Inner Join:     Syntax:   SELECT <column_list> FROM <first_table> INNER JOIN <second_table> ON (join_condition {AND join_condition})
                          -> INNER JOIN will include all rows that satisfy the join condition (bool expression(s)).
                          -> You can use other SELECT clauses as well, for example WHERE
                          -> USING(<column_list>) instead of "ON ...", tests for equality of columns. They need to exist in both tables.
                          -> We can easily join multiple tables in a row by doing: FROM X INNER JOIN Y USING() INNER JOIN Z USING().
                             This will do ((FROM X INNER JOIN Y USING()) INNER JOIN Z USING()).
                          -> 1. It checks values in join_condition_columns in both tables, 
                             2. It creates a temporary table with all matching rows, merging them,
                             3. SELECT returns specified columns.
                      
Left Join:      Syntax:   SELECT <column_list> FROM <first_table> LEFT JOIN <second_table> ON (join_condition {AND join_condition}).
                          -> LEFT JOIN returns all rows from the <first_table> and the matching rows from the <second_table>.

Right Join:     Syntax:   Same as LEFT JOIN but for <second_table>.

Full (outer) Join:        FROM <first_table> FULL [OUTER] JOIN <second_table> ON (join_condition).
                          -> Returns resultset that is a combination of LEFT and RIGHT JOIN on the join_condition.
                          -> When writing "ON 1 = 1", it does the same as a cross join.

Cross Join:     Syntax:   SELECT <column_list> FROM X CROSS JOIN Y. Without join_condition
                          -> The result is a cartesian product of the two sets of rows.

Self Join:      Syntax:   Uses other JOINS such as INNER JOIN or LEFT JOIN.
                          -> It joins a table with itself. Useful to compare rows within a table or query hierarchical data.
                          -> Important: Use table aliasing. Referencing the same table more than once in a query gives an error.
                          -> Example: SELECT <e.first_name> employee, <m.first_name> manager
                                      FROM <employees> e INNER JOIN <employees> m ON <m.employee_id> = <e.manager_id>;

Oracle Joins:   General:  You can build exclusive outer joins with "ON table.id WHERE table.id IS NULL" clause.
                          -> Like this all rows that fulfill the join_condition are excluded.
                          -> In a FULL JOIN this is done with "WHERE <first_table.id> IS NULL OR <second_table.id> IS NULL".
